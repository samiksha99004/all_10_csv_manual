0. GOAL
-------
Detect an SSH brute-force attack LIVE on the victim machine.
While the attack runs, the victim prints every ~2 seconds:
  - the attacker IP
  - NORMAL or ABNORMAL for the current window
  - a guess table of which attack it might be (when ABNORMAL)
  - cumulative counts
All capture, conversion, feature selection and scoring happen ON THE VICTIM.
Windows is not part of the live pipeline. The attacker only attacks.

Status today: the monitor script and the model bundle are written and pushed
(commit a070f6c). The monitor was tested only in CSV mode on a saved capture
(result matched the earlier offline run: 711 of 797 flows flagged). The capture
and the converter have NOT run live yet. Several setup items are still open (section 5).

6. WHAT THE MONITOR DOES (for the other AI, to check the code if needed)
-----------------------------------------------------------------------
- Every 2 seconds it lists ~/ids/pcap/seg_*.pcap, skips the NEWEST file (tcpdump may still
  be writing it), and converts each new file with the Java converter.
- It reads the converter's CSV, maps the Java column names to the 78 training features
  (table JAVA in live_monitor.py), and keeps only rows where all 78 are finite.
- Level 1 (level1_binary_xgb.json) says attack or benign. Level 2 (level2_multiclass_xgb.json)
  names the attack for the flows level 1 flagged. Level-2 indexes map to classes through
  attack_classes.json and meta.json.
- Verdict per window: ABNORMAL if any flow is flagged, otherwise NORMAL.
- Attacker IP = the source IP that sends the most flows to destination port 22 across all windows.
- It redraws the screen (ANSI clear) every --refresh seconds.
- Test result on the saved SSH capture (ssh_attack_java.csv, CSV mode): 797 flows,
  711 flagged, labels Infilteration 354, SSH-Bruteforce 230, Slowloris 127. Matches the
  earlier offline run.

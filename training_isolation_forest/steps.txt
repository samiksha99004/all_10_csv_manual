ISOLATION FOREST - HOW TO RUN
=============================

What this does
--------------
Trains an Isolation Forest on the cleaned CICIDS2018 dataset with an 80% train / 20% test
split per class (no validation set), then tests it and reports, for every attack type, how
many attacks out of 100 were caught, plus overall accuracy.

Isolation Forest is unsupervised. It learns what NORMAL traffic looks like and flags anything
unusual. It answers only "normal" or "attack"; it cannot name the attack type. The per-attack
numbers use the true labels to count how many of each attack were flagged.


Before you start
----------------
1. The cleaned file must exist:  original_csv\cicids2018_full_cleaned.csv
2. Close Chrome and other heavy apps (this laptop has little free memory).
3. Open a terminal in the project folder:  F:\all_10_csv_manual
   (all commands below are run from there, not from inside this folder)


Run these 3 steps in order
--------------------------
Step 1 - build the 80/20 split (about 3 minutes)
    python training_isolation_forest\1_prepare_data.py

    Reads the 4.8 GB CSV in 200,000-row chunks (never all at once), keeps every attack row
    and a random 1,000,000 Benign rows, splits every class 80% train / 20% test, and saves
    the arrays to training_isolation_forest\data\ (about 650 MB, not uploaded to GitHub).

Step 2 - train the model and choose the alarm threshold (about 3-8 minutes)
    python training_isolation_forest\2_train_isolation_forest.py

    Fits 200 trees on the Benign rows of the training split, using all CPU cores, then
    scores every training row in chunks and picks the threshold that gets the most classes
    to 95% or more. Writes isolation_forest.joblib, model_config.json and train_report.txt.

Step 3 - test on the 20% the model never saw (about 2 minutes)
    python training_isolation_forest\3_evaluate_test.py

    Writes test_report.txt (the results), test_metrics.json, per_attack_recall.png and
    score_distribution.png.

Steps must run in this order. Step 2 needs step 1's data; step 3 needs step 2's model.
If a step fails with "Unable to allocate" or stops with no error, memory ran out:
close more apps and run that step again.


Reading the results (test_report.txt)
-------------------------------------
- Overall accuracy: share of all test flows labelled correctly (normal vs attack).
- Per-class rate: for an attack, how many of 100 were caught (recall);
  for Benign, how many of 100 normal flows were NOT flagged.
- "< 95%" marks classes that miss your target.
- The last table shows the trade-off: how many attacks are caught if you accept
  1%, 2%, 5%, 10% or 20% false alarms on normal traffic.


Settings and where they come from
---------------------------------
(in if_common.py; change them there and re-run steps 2 and 3, step 1 is not needed again)

    N_ESTIMATORS = 200   Tests across 140 datasets found 100-200 trees is the sweet spot;
                         more trees add stability, not accuracy.
    MAX_SAMPLES  = 256   Rows used to build each tree, as in the original Isolation Forest
                         paper (Liu, Ting & Zhou, 2008). Small samples isolate outliers better.
    N_JOBS       = -1    Uses every CPU core.

Other choices, based on published CSE-CIC-IDS2018 work:
- Trained on normal traffic only. Large attack classes (DDoS-LOIC-HTTP has 460,000 training
  rows) would otherwise be learned as "normal".
- The alarm threshold is chosen from the data, not the default of 0. One published
  CSE-CIC-IDS2018 study reported 99.1% detection this way.
- Features are log-transformed, because rates up to 1.8 billion would make most random
  splits useless.

If results are below 95%, try (then re-run steps 2 and 3):
- MAX_SAMPLES = 1024 or 4096 (more detail per tree)
- N_ESTIMATORS = 300


Honest expectation
------------------
Isolation Forest finds rare, unusual traffic. Attacks that look like normal traffic
(especially Infilteration) are hard for it. So are attacks that come in huge, very similar
floods (DDoS / DoS), because they form dense groups rather than rare outliers. Expect
several classes to fall below 95%. The supervised XGBoost model (training_xgboost\) is
stronger per attack. The test report will show exactly where this model stands.

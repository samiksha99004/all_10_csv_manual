SSH BRUTE-FORCE LIVE TEST - FRESH RUNBOOK (Kali to Kali, Patator, 1-second flows)
==============================================================================
Start from zero. No earlier CSV or pcap is used. The old attack CSVs were deleted.

RULES
-----
- No value is edited, scaled by hand, or relabelled to improve a result.
- Units come from the converter. The Java CICFlowMeter-v3 writes time in MICROSECONDS,
  the same as the training data, so no conversion is applied. If a value is not in
  microseconds, STOP and report it.
- Every setting change on Kali is written in this file BEFORE the attack runs.
- If a command fails, copy the exact error text. Do not guess a fix.
- Do not change sshd or Patator settings to chase a result.
- Commands marked <CHECK> must be checked on the machine first. Do not guess them.

WHY THIS SETUP
--------------
- Training SSH flows: median 0.37 s, 22 forward / 22 backward packets, Flow IAT Mean 8,686 us.
- Python cicflowmeter is NOT used: its column values differ from training.
- Java CICFlowMeter-v3 is the converter CICIDS2018 used.
- The flow timeout is set to 1 second, so each flow row covers at most 1 second.

MACHINES
--------
ATTACKER = Kali VM (Patator, tcpdump, tshark, Java CICFlowMeter-v3)   IP: <ATTACKER_IP>
VICTIM   = second Kali VM with openssh-server                         IP: <VICTIM_IP>
WINDOWS  = F:\all_10_csv_manual  (trained model lives here)
Both VMs must be on the same network. Record the VirtualBox network mode of both VMs.

FILE NAMES USED
---------------
pcap (capture)      : kali_patator.pcap
flow CSV (converter): kali_patator_1s.csv   (renamed from the converter's output name)
Windows target      : F:\all_10_csv_manual\kali_patator_1s.csv

=============================================================================
STEP 0 - CHECK NETWORK ON BOTH VMS
=============================================================================
Run on the ATTACKER Kali:
    ip -br a                       (note the interface with <ATTACKER_IP>, e.g. eth0)
    ip -br a | grep -E "eth|enp"   (shorter list of network interfaces)

Run on the VICTIM Kali:
    ip -br a                       (note <VICTIM_IP>)

Test the link from the attacker:
    ping -c 10 <VICTIM_IP>
    Record the average round-trip time. Expected: well below 0.4 s.

=============================================================================
STEP 1 - VICTIM KALI: SSH SERVER AND TEST ACCOUNT
=============================================================================
Run on the VICTIM Kali:
    sudo apt update
    sudo apt install -y openssh-server
    sudo systemctl enable --now ssh
    sudo systemctl status ssh           (must show: active (running))

Create the test account (use a name you will use again in step 5):
    sudo adduser <USER>                 (set a password. Write it down; it goes in the wordlist)

Record the sshd settings as they are (do not change them):
    grep -v '^#' /etc/ssh/sshd_config | grep . > ~/sshd_used.txt
    cat ~/sshd_used.txt

Check whether PAM adds a delay after a failed login (a possible cause of the gap):
    grep -r -i faildelay /etc/pam.d/ || echo "no faildelay line"

Record the result of these checks in the RECORD section.

=============================================================================
STEP 2 - ATTACKER KALI: TOOLS
=============================================================================
Run on the ATTACKER Kali:
    sudo apt update
    sudo apt install -y patator tcpdump tshark wireshark-common
    patator ssh_login --help             (read the options; do not guess flags)
    which capinfos                       (capinfos comes from wireshark-common)

STEP 3 - ATTACKER KALI: WORDLIST
=============================================================================
Create a wordlist that contains the victim's real password for <USER> at a known line.

    cd ~

    wc -l wordlist.txt                  (record the number of lines)
    grep -n -x '<USER_PASSWORD>' wordlist.txt   (record the line number of the real password)

        old: ____________________   new: activityTimeout = 1000000

=============================================================================
STEP 5 - ATTACKER KALI: START CAPTURE, THEN ATTACK
=============================================================================
5a. Confirm the capture interface (from step 0). Set it:
        IFACE=<interface_name>

5b. Start the capture BEFORE the attack. Use a second terminal for the attack:
        sudo tcpdump -i $IFACE -w kali_patator.pcap host <VICTIM_IP> and port 22

5c. In a second terminal, run the attack with the wordlist from step 3:
        patator ssh_login host=<VICTIM_IP> user=<USER> password=FILE0 0=$HOME/wordlist.txt -x ignore:mesg='Authentication failed.'
    Confirm the options match the output of: patator ssh_login --help  (step 2)
    Do not change the thread count. Note the start time and the end time:
        start: ________   end: ________

5d. Let the attack finish. Then stop tcpdump with Ctrl+C in its terminal.

5e. Check how long the capture lasted:
        capinfos kali_patator.pcap
    Record the "Capture duration" value. If it is far from the expected length, stop
    and report it before going on.

=============================================================================
STEP 6 - ATTACKER KALI: CHECK THE PCAP BEFORE CONVERTING
=============================================================================
6a. Count the packets on port 22:
        tshark -r kali_patator.pcap -Y "tcp.port==22" | wc -l

6b. Count the TCP connections (shows whether Patator reused connections):
        tshark -r kali_patator.pcap -q -z conv,tcp | tail -5
    Record the number of TCP conversations.

6c. Measure the gap between packets from the pcap (training: about 8,686 us in Flow IAT Mean):
        tshark -r kali_patator.pcap -Y "tcp.port==22" -T fields -e frame.time_delta_displayed | sort -n | awk '{a[NR]=$1} END{print "median gap (s) =", a[int(NR/2)+1]}'
    Record the number. This is measured, not changed. It measures every port-22
    packet, not each flow, so it is a close proxy only.

=============================================================================
STEP 7 - ATTACKER KALI: CONVERT PCAP TO FLOW CSV (Java CICFlowMeter-v3)
=============================================================================
7a. Run the converter with the command from step 4e, with kali_patator.pcap as input.
    Find the output file the converter created:
        ls -lt | head -5

7b. Rename it to the file name used everywhere in this plan:
        mv <CONVERTER_OUTPUT>.csv kali_patator_1s.csv

7c. Check the header is the Java format (starts with "Flow ID,Src IP,Src Port,Dst IP,Dst Port,Protocol,Timestamp,Flow Duration"):
        head -1 kali_patator_1s.csv

7d. Count all rows, then attack rows (source = attacker, destination port 22):
        wc -l kali_patator_1s.csv
        awk -F, 'NR>1 && $2=="<ATTACKER_IP>" && $5=="22"' kali_patator_1s.csv | wc -l

7e. VERIFICATION GATE (stop if it fails):
        awk -F, 'NR>1 {if($8+0>m)m=$8+0} END{print "max Flow Duration (us) =", m}' kali_patator_1s.csv
    The number must be <= 1000000. If it is larger, the timeout in step 4 did not take effect.
    Go back to step 4b.

7f. Check the units. Values in the Flow Duration column are whole microseconds, so the
    smallest non-zero value should be above 1 and not in fractions of a second:
        awk -F, 'NR>1 && $8+0>0 {print $8}' kali_patator_1s.csv | sort -n | head -3

7g. Measure packets per flow for the attack flows (training median: 22 forward, 22 backward):
        awk -F, 'NR>1 && $2=="<ATTACKER_IP>" && $5=="22"{print $9, $10}' kali_patator_1s.csv | sort -n -k1,1 | awk '{f[NR]=$1; b[NR]=$2} END{print "median fwd =", f[int(NR/2)+1], " median bwd =", b[int(NR/2)+1]}'
    Columns: $9 = Total Fwd Packet, $10 = Total Bwd packets.

7h. Record the time range covered (timestamps are the flow start time):
        awk -F, 'NR>1{print $7}' kali_patator_1s.csv | sort | sed -n '1p;$p'
